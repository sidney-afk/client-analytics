# SyncLinear replacement: closure ledger and exit certificate

Status: analysis-only. This ledger adds no runtime behavior, data migration, flag change, Edge Function deployment, n8n edit, client-link change, or provider action.

This is the deliberately exhaustive companion to the [replacement strategy](2026-09-03-synclinear-linear-exit-strategy.md) and its [deep-cutover addendum](2026-09-03-synclinear-linear-exit-deep-dive.md). It converts the remaining investigation perimeter into closure obligations. It is **not** a claim that all obligations have been met.

## The decision this ledger supports

Linear is not ready to be disabled. The safe decision is available only when every row below has an evidence-bearing disposition:

1. **Native and proved:** the client/staff action works with Linear egress denied.
2. **Compatibility retained:** an old browser/request shape reaches a native terminal receipt during its defined support horizon.
3. **Archived:** historic material is privately retrievable without Linear and has an owner-approved retention disposition.
4. **Retired:** the entry point is no longer reachable, after a measured zero-caller/zero-debt period and a replacement/removal review.
5. **Explicitly out of product scope:** an owner has signed the operational/legal disposition.

“No source match,” “outbound mode off,” an empty anonymous query, a green mocked test, or a successful provider call does not satisfy a row. A protected-table `401` means **unproven**, not empty. A checked-in Edge Function or migration means **source behavior**, not necessarily serving behavior: `docs/ops/EF_DEPLOY_MANIFEST.md:3-7`; `migrations/README.md:1-10`.

The client invariant remains stricter than every other requirement. At every intermediate state, an existing share URL must continue to load its content and preserve every offered approval, tweak, note, comment, or other action as either one durable native result or one visible native pending/recovery state. It may never become a blank view, a false empty success, a silent local-only save, a generic sign-in/`401` remedy, or a request to use Linear. The frozen Calendar and Samples writer rule therefore controls all work here: `AGENTS.md:3-14`.

This ledger does not propose a Supabase publishable-key rotation, an RLS/raw-read tightening, or a writer re-gate as a Linear-exit shortcut. Those are separate access-boundary programs and must not be bundled into the client-continuity cutover: `docs/audits/2026-09-03-synclinear-linear-exit-deep-dive.md:288-296`.

## Evidence vocabulary

| Label | Meaning | What it does **not** mean |
| --- | --- | --- |
| `SOURCE-REACHABLE` | A real route/control/dispatcher was traced to the cited provider or provider-shaped branch in the checked-in source. | That production serves this revision or that the branch always runs. |
| `SOURCE-NEGATIVE` | The investigated entry did not reach a direct Linear call in the inspected source path. | That an imported function, deployed revision, workflow, or external service cannot depend on Linear. |
| `DEPLOYMENT-UNPROVEN` | No serving function/view/trigger/workflow fingerprint was captured. | That current source may be deployed by inference. |
| `LIVE-AGGREGATE` | A date-stamped, public-safe count/status observation exists in the strategy/addendum. | Completeness of protected state, provenance, or row-level correctness. |
| `EXTERNAL-UNPROVEN` | The dependency could live in provider admin, n8n, a personal integration, an operator bookmark, or another system outside the repository. | Safety to ignore it. |

No closure row may advance from `SOURCE-REACHABLE` or `SOURCE-NEGATIVE` directly to “retired.” It must first have an observed serving contract, a provider-egress-denied test, and an owner for its rollback/recovery behavior.

## Required evidence package before each exit decision

The package is private and aggregate-only. It must not put a client display name, slug, share token, content body, attachment URL, API token, or secret in this public repository, CI output, or commit history.

1. **Serving manifest:** Pages build, every client-critical Edge Function version/hash/auth/JWT/CORS posture, database catalog fingerprint, active flags and their failure defaults, GitHub workflow revisions, n8n export revisions, and provider admin inventory.
2. **Client compatibility matrix:** current/fresh, one-release-old, two-release-old, cached, dirty, offline/reconnect, BFCache, missing/slow/malformed flag, provider-denied, rate-limited, response-lost, and two-tab cases for every offered client action.
3. **Native action-conservation report:** aggregate intent/receipt/event/card/component/thread/notification/materialization counts, duplicate/missing/aged buckets, and declared exception states.
4. **Semantic parity report:** lifecycle/archive, hierarchy, approval revision, identity/deep link, comment/reply/history, assignee/project/team, Workload plan/date, and asset retrieval results.
5. **External closure inventory:** all trigger roots, provider-side integrations, credential consumers, webhooks, manual scripts/runbooks, dispatches, retries, and restore paths, each with owner and retirement/compatibility disposition.
6. **Exit Archive manifest:** cursor-complete export counts/hashes, asset bytes/readbacks, crosswalks, outbox/receipt state, retention/legal disposition, and isolated provider-denied restoration/retrieval drill.
7. **Alert-delivery evidence:** intentionally fail only a test-scope canary and show that a named human receives the alert. A failed job without delivery evidence is not a watcher.
