# Native urgent action UI preparation

SOURCE_ONLY, uninstalled. Four existing staff callers (Calendar, Samples and their two review queues) now admit a native video ID while preserving video/Tweaks Needed eligibility and the existing surrounding role gates. Their shared dispatcher uses the authenticated Supabase origin for `native_urgent_dispatch`; it sends only action, client slug, deliverable ID, card ID, surface and the current video status timestamp. Recipient identity stays server-owned. URL-only legacy cards retain the existing webhook and receive no staff credential headers.

The existing confirmation and button controls remain. Native success requires an HTTP success plus `ok:true`, `delivery:sent`, and nonempty dispatch ID/Slack timestamp before the Sent marker is persisted. If the card/client/native ID/status round changes during delivery, the UI reports delivery for the original round and does not mark the current round Sent.

A local-storage hold is written before native transport and is keyed only by native scope and canonicalized round timestamp. Storage failure stops visibly before sending. Unknown, lost, timed-out or malformed responses retain the hold without expiry; re-render, reload and repeated confirmation cannot silently resend. The UI says **Check delivery** and directs staff to inspect #video-editing manually. Only an explicit server `delivery:not_sent`, `retry_safe:true`, `ok:false` response releases the hold for another user action. An acknowledged send keeps the local hold even if marker persistence fails.

This hold is not global or durable exactly-once delivery: separate browsers/devices or cleared browser storage remain outside it. No automatic resolution, local timeout expiry or hidden retry is provided. Manual Slack reconciliation remains necessary for unknown outcomes; this preparation does not authorize another message or deletion of retained evidence.

Validation: `test/native-urgent-ui.js` passes 25 actual extracted-source VM groups for all four native/legacy transports, strict acknowledgements, storage failures, unknown outcomes across reload, equivalent timestamp round binding, repeated confirmation, pretransport refusal, current-context drift, persistence failure and client-link refusal. The three existing Calendar urgent badge, urgent persistence and Kasper urgent tests also pass. Synthetic transport/DOM fixtures prove no live message, installed gateway, actual browser layout or server delivery. Existing frozen Calendar/Samples writer authentication is unchanged. Backend release and final browser/installed integration remain held for separate review.

Rollback before activation: withdraw unused preparation without data effects. After an attempted native send, retain the local hold and server/delivery evidence, preserve known marker state and reconcile manually; reverting to a URL-only sender or clearing an unknown hold does not establish that delivery failed.
