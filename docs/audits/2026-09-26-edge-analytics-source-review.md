# Analytics mirror Edge Function failure paths (2026-09-26)

Source baseline: `3f5bd46e6086911ae2a7bb0d32507f03d5a44da8`. This proposal-only review covers `supabase/functions/analytics-read/index.ts` and `supabase/functions/analytics-write/index.ts`. It made no endpoint call, read no client rows, and changed no function or live system. The owning `docs/truth/ENDPOINTS.md` says the admin Clients list uses `analytics-read`, while per-client analytics reads are not yet wired into the page.

The shared contract already has role-key/client-token gates for reads, a dedicated write key for writes, and a disabled-by-default write flag. The findings below concern failures **after** those boundaries, not a proposal to alter who can call either route.

| Source finding | Evidence and consequence | Proposed follow-up |
|---|---|---|
| A failed client read-flag query looks like a deliberate disable. | `analytics-read/index.ts:51-57` discards the Supabase `error` from `syncview_runtime_flags`; a failed query yields no `data`, so `flagOn()` returns false. Lines 162-164 then return `503 mirror_read_disabled`. The caller cannot distinguish a flag set to off from a flag read that failed. This applies to the future client-link analytics path, not the current admin list. | Check the query error separately and return a distinct service failure. Preserve the actual off-flag refusal and the client-token gate. |
| The admin Clients list can report success with unknown authority. | `analytics-read/index.ts:134-141` reads `client_profiles_authority` but ignores its `error`, then returns `ok: true` and `authority: null`. A failed authority read therefore appears as a normal unknown value beside otherwise loaded profile rows. This is a source possibility, not an observed UI failure. | Check the authority read result and expose a distinct failure or explicit partial response; add a mocked error-path test. |
| Valid JSON `null` becomes an internal error in both routes. | `analytics-read/index.ts:122,128,145` and `analytics-write/index.ts:131-133` cast parsed JSON to an object before reading properties. `null` parses successfully, then property access throws into the outer `500 read_failed` or `500 write_failed` catch. Malformed JSON and missing fields otherwise receive client-input responses. The write key is checked before parsing. | Require a non-null object (and reject arrays if the contract expects a map) before property access, returning a stable 400 error without changing authentication or the write flag. |

`test/sheets-mirror-policy.js` checks source-level access and receipt invariants but does not execute these three failure branches with mocked Supabase responses. A later implementation should add isolated handler tests for a flag-read error, an authority-read error, and JSON `null` on each route. No live frequency, actual missing rows, or deployment state is inferred here.
